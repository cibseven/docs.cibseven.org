CIB seven 3.0.0 CE - Release Notes

Release Date: November 20, 2026

Highlights

  • Platform Jakarta EE 11 (EL 6.0, JAX-RS 4.0), Spring Boot 4.1 and Spring Framework 7 as the only Spring line, Java 17 as the minimum and Java 25 as a new supported version, with Java 25 Docker images
  • Jackson 3 The REST API, Spin JSON, the external task client, the Spring Boot starters, CIB seven Run and the webclient use Jackson 3; deprecated -jackson2 artifacts of Spin and the external task client remain for applications that cannot move yet
  • Legacy web applications removed The old Camunda Cockpit, Tasklist and Admin are no longer part of the distributions and the Spring Boot starters; use the CIB seven webclient
  • Ad hoc sub process The BPMN adHocSubProcess is supported from the model API to the REST API
  • Agentic ad hoc sub process (beta) An ad hoc sub process driven by the AI Agent Connector, which chooses the activities to start
  • AI Agent Connector Process variables and documents (PDF, images, text) as model input; the chat memory is kept per process instance (since 2.2.4)
  • MCP The REST API MCP Plugin ships with CIB seven Run and is switched on with MCP_ENABLED=true
  • External tasks Retry time cycle for external tasks and a fetched entry in the external task log
  • Modeler Diagrams and forms organized in folders and projects, process keys and form ids unique per folder (cibseven-modeler 1.3.0)
  • Webclient Frontend plugins, configurable deep links, a new header navigation, and UI permissions read from the user’s own authorizations
  • Database The webclient tables are an optional schema component (webclientExtensionsEnabled)
  • Direct Provider The Direct Provider of the webclient, which calls the engine in the same JVM instead of over the REST API, is no longer beta
  • Security Attachments and comments are protected by permission checks, JUEL scripts follow the restrictions of a customized expression manager, a hardening adds a deny list for expressions and scripts, active by default since 3.0.0, and opt-in allow lists for task types, script languages and connector endpoints, and the webclient connects only to configured engine REST servers (since 2.2.5); the task filter expression whitelist is enabled by default and the first-admin setup is offered only on an unconfigured engine (since 2.2.4); 270 CVEs and security advisories and Camunda Security Notice 157 resolved since 2.2.0 (19 Critical, 71 High, 113 Medium, 67 Low)

Breaking Changes

The update guide from 2.2 to 3.0 describes the migration steps.

  • Java 17 baseline. All CIB seven 3.x artifacts are compiled to Java 17 bytecode and no longer load on Java 11: the embedded engine, the standalone DMN engine, the external task client, the model APIs, Spin, Connect, Commons and the test libraries. Applications and external task workers must run on Java 17, 21 or 25. OSGi bundles require osgi.ee JavaSE 17. See Java 17 is required.
  • Jakarta EE only; the -jakarta artifacts are renamed. The javax (Java EE 8) variants are removed, and the unsuffixed artifacts are now the Jakarta ones: replace cibseven-engine-rest-core-jakarta with cibseven-engine-rest-core, cibseven-engine-rest-jakarta with cibseven-engine-rest, cibseven-engine-cdi-jakarta with cibseven-engine-cdi, cibseven-ejb-client-jakarta with cibseven-ejb-client and cibseven-spin-dataformat-xml-dom-jakarta with cibseven-spin-dataformat-xml-dom. Application servers with javax APIs (Tomcat 9, WildFly 26 and older, JBoss EAP 7) are no longer supported. ServletProcessApplication is now based on jakarta.servlet and deprecated in favor of JakartaServletProcessApplication. See Java EE variants removed.
  • Jakarta EE 11 and EL 6.0. All modules are built against Jakarta EE 11.0.0. cibseven-juel no longer contains its own copy of the EL API (org.cibseven.bpm.impl.juel.jakarta.el): custom EL classes such as an ELResolver, and process applications that override getElResolver(), getBeanElResolver() or initProcessApplicationElResolver(), must import jakarta.el and be recompiled. EL 6.0 removed ELResolver#getFeatureDescriptors, so custom resolvers that override or call it no longer compile; subclasses of the JUEL ExpressionFactoryImpl that override coerceToType must use <T> T coerceToType(Object, Class<T>). cibseven-engine-dmn brings jakarta.el-api 6.0.1 and the EL implementation Expressly 6.0.0; exclude Expressly from WAR and EAR files for Tomcat, WildFly and JBoss EAP, whose EL implementation applies. EL 4.0 is not supported; Jakarta EE 10 servers (e.g. Tomcat 10.1, JBoss EAP 8.1) remain compatible. Builds that import the Jakarta EE BOM next to CIB seven should use 11.0.0. See Jakarta EE 11, Jakarta Expression Language 6.0 and ELResolver#getFeatureDescriptors removed.
  • JAX-RS 4.0. The REST API (cibseven-engine-rest-core) and its wars are built against Jakarta RESTful Web Services 4.0. Custom JAX-RS resources, providers and REST extensions must run on JAX-RS 4.0, which dropped Link.JaxbLink / JaxbAdapter and @ManagedBean support. The REST API war of the Tomcat distribution ships RESTEasy 7.0.5.Final; RESTEasy 7 no longer has resteasy-netty4, so an embedded RESTEasy server needs resteasy-undertow or resteasy-jdk-http. See Jakarta RESTful Web Services 4.0.
  • Jackson 3 in the REST API. engine-rest uses Jackson 3 (tools.jackson); the JSON on the wire is unchanged. Jackson types in its public Java API are Jackson 3 types (tools.jackson.databind.ObjectMapper, ContextResolver<ObjectMapper> for REST extensions). JacksonConfigurator.configureObjectMapper(ObjectMapper) is replaced by configureObjectMapper(), which returns the configured JsonMapper. Applications that register com.fasterxml.jackson.jakarta.rs.json.JacksonJsonProvider must register CibsevenJacksonJsonProvider instead. See Jackson 3.
  • Jackson 3 in Spin and the external task client. cibseven-spin-dataformat-json-jackson, cibseven-spin-dataformat-all and cibseven-external-task-client use Jackson 3; stored JSON keeps the Jackson 2 format, and object variables written by 2.x are read as Jackson 2 read them (e.g. Map and Set properties with enum keys, classes with @JsonUnwrapped, and, with the Spring Boot starter, classes with a constructor without parameters next to one taking all properties). Data format configurators get an immutable Jackson 3 mapper (use rebuild()). Where Spin sees the annotations of variable classes (not in Run and the Tomcat distribution), the annotations of jackson-databind 2 (com.fasterxml.jackson.databind.annotation) are ignored, class ids on properties of type Object are no longer read without a PolymorphicTypeValidator, and @JsonInclude(content = NON_NULL) on a class drops null entries of its Map properties. Reading such a variable stores its new form, so back up the database before the update, and in a rolling update update all nodes before such variables are read. Applications that cannot move yet can use the deprecated cibseven-spin-dataformat-json-jackson2, cibseven-spin-dataformat-all-jackson2 and cibseven-external-task-client-jackson2 artifacts, which will be removed in 3.1.0; the two variants must not be on one classpath (the client fails with TASK/CLIENT-01035). Spin JSON needs json-path 3.0.0: applications using spring-boot-starter-parent must import the cibseven-bom before spring-boot-dependencies or set json-path.version, otherwise Spin fails with SPIN/JACKSON-JSON-01018.
  • No Jackson 2 in the Spring Boot starters, Run and the wars. cibseven-bpm-spring-boot-starter-rest and -webapp no longer bring Jackson 2. The core of CIB seven Run has no Jackson 2 unless the webclient or the AI Agent Connector is enabled, so process engine plugins and delegates in configuration/userlib/ that need Jackson 2 must bring it. The REST API war on WildFly excludes the server’s Jackson 2 modules. The Jackson modules of CIB seven on WildFly have the slot cibseven instead of their Jackson version; a process application whose jboss-deployment-structure.xml names the old slot does not deploy (WFLYSRV0179), see Jackson modules in jboss-deployment-structure.xml. The starter’s Jackson 2 configurators (CamundaJacksonFormatConfiguratorJSR310, …Jdk8, …ParameterNames) are only active with the -jackson2 Spin variant and are deprecated.
  • Spring Boot 4.1 and Spring Framework 7 only. Spring Boot 3 and Spring Framework 5 and 6 are no longer supported. The Spring Boot starters and CIB seven Run are built on Spring Boot 4.1; the former -4 artifacts (e.g. cibseven-bpm-spring-boot-starter-4, cibseven-bpm-run4) are Maven relocations to the unsuffixed ones and will be removed in a future release. cibseven-engine-spring is built on Spring Framework 7, cibseven-engine-spring-6 is removed and cibseven-engine-spring-7 relocates to cibseven-engine-spring. The webclient (cibseven-webclient-web) runs on Spring Boot 4 only; cibseven-webclient-web-spring-boot-4 is a relocation. CIB seven 3.0 supports Spring Boot 4.1 with the Jackson 3 version it manages (3.1.7); Spring Boot 4.2 and Jackson 3.2 are not supported yet, since the REST API loses the resource type of filters with Jackson 3.2, and will follow with CIB seven 3.1. See Spring Boot Version Compatibility and Spring Boot 4 and Spring Framework 7 are required.
  • Quarkus 3.33. The Quarkus Extension is built on Quarkus 3.33.3 instead of 3.27; applications that use it must run on Quarkus 3.33.x. See Quarkus 3.33 extension update and Quarkus Version Compatibility
  • run4 becomes run. The Spring Boot 4 distribution of CIB seven Run is now the only one, named cibseven-bpm-run. The run4 Docker images are no longer built; use the run images.
  • Legacy Camunda web applications removed. Cockpit, Tasklist, Admin and Welcome (/camunda/app/…) are no longer shipped with the Tomcat and WildFly distributions, CIB seven Run, the Spring Boot starter-webapp and the BOM, and the cibseven-webapp-* wars are no longer published. Use the CIB seven webclient (/webapp). Plugins written for the legacy web applications no longer work. See Configuration Changes for the removed properties.
  • WildFly 28 distribution removed. The WildFly distribution is based on WildFly 42; the javax distributions for Tomcat 9 and WildFly 26 are removed as well.
  • JUnit 4 test support removed. ProcessEngineRule and DmnEngineRule are no longer JUnit 4 rules, and ProcessEngineTestCase no longer extends junit.framework.TestCase. The Spring Boot test starter no longer brings the JUnit Vintage engine, and JUnit 3-style test*() methods of ProcessEngineTestCase subclasses need @Test. Migrate process tests to JUnit 5, e.g. with ProcessEngineExtension from cibseven-bpm-junit5, see JUnit 4 and JUnit 3 test support removed.
  • GraalJS 25. The distributions update GraalJS from 21.3 to 25.0.1. Applications that embed the engine and bring GraalJS themselves declare org.graalvm.js:js with <type>pom</type>, and add com.ibm.icu:icu4j if their code or scripts use com.ibm.icu, which GraalJS no longer brings (the distributions keep icu4j 71.1). Manual Tomcat and WildFly installations replace the GraalJS jars and modules. A GraalJS context created with js.nashorn-compat needs js.ecmascript-version, otherwise its scripts are limited to ECMAScript 5. A script still stores an integer in the int range that comes from Java as a long as Integer, as in 2.2, but the result of arithmetic with it is now Double, so Java code that casts such a variable to Integer fails with a ClassCastException; the new process engine property javaScriptNumberNarrowing controls this. Incident messages of failed scripts no longer contain org.graalvm.polyglot.PolyglotException, so monitoring rules, alerts and tests that look for it need to be adapted. See Java 25 and GraalJS 25, Number types in JavaScript scripts and Script error messages.
  • MIME types of file variables. Variables.fileValue(File) detects the MIME type with Jakarta Activation 2.1 and Eclipse Angus. Manual Tomcat installations copy jakarta.activation-api and angus-activation to lib/; web applications that use the shared engine of Tomcat must not bundle them, otherwise every file gets application/octet-stream. Manual WildFly installations take the modules cibseven-commons-typed-values and cibseven-engine from the 3.0 distribution. See Jakarta Activation and MIME types of file variables.
  • New index on the historic job log. The update script creates ACT_IDX_HI_JOB_LOG_DEPLOYMENT on ACT_HI_JOB_LOG(DEPLOYMENT_ID_) and fails if an index of this name exists, on Oracle also if another index covers this column; drop such an index before the update. Building the index on a large job log takes time, and on PostgreSQL, Oracle and SQL Server it blocks writes to ACT_HI_JOB_LOG, and with them the job executor. See New database indexes.
  • The webclient tables are an optional schema component, off by default for embedded engines. The modeler, chat and notification tables are created with the engine schema only if the new process engine property webclientExtensionsEnabled is true (default false). It replaces modelerEnabled (default was true), which remains as a deprecated alias. The Tomcat, WildFly and Run distributions set it to true; an application that embeds the engine (e.g. with the Spring Boot starter) together with the webclient must set it. When the engine reports no webclient tables, the modeler is switched off regardless of cibseven.webclient.modeler.enabled, and its endpoints answer 404; engines before 3.0 and a webclient whose tables have a DataSource of their own (cibsevenDataSource) behave as before, see Engine Switch. The SQL scripts for these tables ship separately as <db>_extensions_<version>.sql and <db>_extensions_2.2_to_3.0.sql, see Database Schema and Webclient database tables are now optional.
  • Webclient configuration. The webclient no longer ships an application.yaml; its defaults are defined in code, and cibseven-webclient.yaml / cibseven-webclient.properties are read in every setup. The framework defaults of the standalone webclient (multipart sizes, spring.jpa.open-in-view, the Swagger UI path, …) apply only when the webclient runs on its own, and it no longer overrides the Spring Boot settings of a host application.
  • Webclient JSON. The webclient reads and writes JSON with Jackson 3 and its own mapper; it no longer defines an objectMapper bean, so an embedding application’s spring.jackson.* settings no longer affect it. JWT handling uses jjwt-gson instead of jjwt-jackson, and public types of cibseven-interfaces changed accordingly.
  • Modeler endpoints require the application ACCESS permission on modeler; authenticated users without it get 403. cibseven.webclient.modeler.authentication.enabled is removed, the modeler always requires authentication. See Authentication.
  • Process keys and form ids are unique per folder in the modeler instead of across all models; several folders may hold models with the same key, and deploying any of them adds a version to the same process definition. The webclient tables need the update script <db>_extensions_2.2_to_3.0.sql (Liquibase changeset 2.2-to-3.0-extensions), which replaces the unique keys with MOD_UK_DIAGRAMS_KEY_FOLDER and MOD_UK_FORMS_FORMID_FOLDER; without it, the webclient keeps working, but keys stay unique across all folders. See Folders.
  • External task retries with a retry time cycle. A camunda:failedJobRetryTimeCycle modeled on an asyncBefore / asyncAfter external task now also limits the external task itself: each fetch consumes one retry, independent of what a worker reports with handleFailure. See Retry Time Cycle
  • AI Agent Connector chat log stored in chunks. The chat log of an activity is written as one variable per model call, cibseven-connect-ai-agent_<activityId>~<eventSeq>, after the single cibseven-connect-ai-agent_<activityId> variable of earlier versions, which is still read. New Features

Ad Hoc Sub Process

  • The BPMN adHocSubProcess element is supported in the model API (AdHocSubProcess, fluent builder), the engine and the REST API. Entering the scope starts nothing; activities without an incoming sequence flow can be started by a client, and the scope completes by its completionCondition or when nothing is active any more
  • RuntimeService#activateAdHocSubProcessActivities(...), createAdHocSubProcessActivation(executionId) and completeAdHocSubProcess(...), and the REST endpoints POST /execution/{id}/ad-hoc-activities/activate and POST /execution/{id}/ad-hoc-activities/complete; they require UPDATE on the process instance or UPDATE_INSTANCE on the process definition
  • Deployments are refused for an ad hoc sub process without activities, with start or end events, with ordering="Sequential" or triggeredByEvent="true"

Agentic Ad Hoc Sub Process (beta)

  • An ad hoc sub process that carries the AI Agent Connector is driven by a model: each turn asks the model which activities to start as tools, feeds their results back, and ends the sub process when the model is done; turn and call limits end it with a BPMN error
  • The agent is told how each tool ended (completed, waiting, interrupted by a boundary event, cancelled) and sees the declared process variables on every model call
  • New element template cibseven-ai-agent-adhoc.json; enabled together with the AI Agent Connector
  • Beta: works for limited use cases and is under active development.

AI Agent Connector

  • New inputs contextVariables and optionalContextVariables: the named process variables are sent to the model after the system prompt; a missing required variable fails the activity before the model is called
  • New input documents: file or bytes variables (PDF, PNG/JPEG/GIF/WebP images, text, JSON, XML, YAML) are sent to the model, up to 5 MiB per document and 10 documents in total
  • The audit trail records which variables and documents were sent (name, type, size, SHA-256), never their values
  • The conversation is written once per step and the chat log once per model call, which reduces history rows at history level full
  • The bundled element templates and the Javadoc no longer suggest passing an API key in a process variable or a credential in the BPMN XML; they point to the server’s OPENAI_API_KEY and say where a token in a header field is stored (since 2.2.5)
  • The default model is gpt-6-luna instead of gpt-5.4-nano, set on the server with CIBSEVEN_CONNECT_AI_AGENT_DEFAULT_MODEL; both element templates show it as the placeholder of the empty Model field, and the agentic ad hoc template recommends a model built for tool calling

External Tasks

  • camunda:failedJobRetryTimeCycle applies to external tasks: each fetch consumes one attempt, the cycle’s interval delays the next one, and a failedExternalTask incident is raised when the last attempt is fetched, so a worker that dies without handleFailure no longer fetches a task forever, see Retry Time Cycle

Security Hardening

The allow list for task types and script languages and the endpoint allow list are off by default, so an engine behaves as before until an administrator sets them. The deny list for expressions and scripts is active by default since 3.0.0, see Breaking Changes; on 2.2.5 it was only active once deniedExpressionAccess was set. (since 2.2.5)

  • Deny list for expressions and scripts: deniedExpressionAccess names what JUEL expressions and scripts must not access: a property or method name (getClass), a type (java.lang.Runtime), an EL function (lang:import) or a member of a type (com.example.Admin#delete). It applies to BPMN and CMMN expressions, JUEL scripts, DMN JUEL expressions and the legacy FEEL engine, not to other script languages. The list is active by default with the defaults class, getClass, java.lang.Class, java.lang.ClassLoader, java.lang.reflect.AccessibleObject, java.lang.invoke.MethodHandle, java.lang.invoke.MethodHandles, lang:import, org.cibseven.bpm.engine.impl.cfg.ProcessEngineConfigurationImpl, java.lang.Runtime and java.lang.ProcessBuilder; a leading minus removes a default (e.g. -lang:import). A newly denied EL function can stop deployed process definitions from loading, so run with expressionHardeningMode=report first, which only logs violations (since 2.2.5)
  • Allow list for task types and script languages: once executionAllowList has entries, process definitions can only use the listed built-in task types (shell, mail, external) and script languages, checked at deployment and at execution. For example, external, mail, juel, groovy, javascript, feel allows mail tasks and denies shell tasks (since 2.2.5)
  • Endpoint allow list for connectors: cibseven.connect.allowed-endpoints restricts the endpoints the HTTP and SOAP connectors (including redirects) and the AI Agent Connector (model endpoint, MCP servers, PostgreSQL and embedding endpoints) may contact, so that targets taken from process variables cannot send requests and credentials elsewhere. Entries have the form scheme://[*.]host[:port], separated by commas. A connector’s own setting (cibseven.connect.<connectorId>.allowed-endpoints, e.g. http-connector, soap-http-connector, cibseven-ai-agent) replaces the global one, and * exempts it (since 2.2.5)

  • Task names, process names and error messages are now rendered as text in the task list navigation, the process lists, the start process dialog and error dialogs, closing a stored cross-site scripting (XSS) issue. Typing ( into the task or process search no longer causes an error (since 2.2.5)
  • The first-run setup could create an administrator without login on an engine that was already administered; it is now offered only on an unconfigured engine (since 2.2.4) (fixes CVE-2026-77226, Camunda Security Notice 171)
  • Attachments of tasks and process instances could be read, downloaded, changed and deleted by any authenticated user who knew their id, since the engine did not check any permission; comments could be read and added the same way. Both are now checked, see Breaking Changes (fixes CVE-2026-109431) (since 2.2.5)
  • JUEL scripts (scriptFormat="juel") ignored the restrictions of a customized expression manager that applied to attribute expressions, so a restricted call such as reflection could still run in a script task. They now resolve through the expression manager, see Breaking Changes (since 2.2.5)
  • The Java External Task Client resolved external entities when it deserialized application/xml object variables, so a crafted variable could make a worker read local files and send requests to other hosts. External entities and DOCTYPE declarations are now rejected, also with a DocumentBuilderFactory supplied by the application (fixes CVE-2026-77224) (since 2.2.5)
  • The Docker images now ship a Java runtime with the fix for CVE-2026-114938 (“Java4Shell”). The ZIP distributions and the Spring Boot starter run on your own JDK: update it to 17.0.21.1, 21.0.13.1 or 25.0.5.1 or later, or start the JVM with -XX:-UseBASE64Intrinsics until you can (since 2.2.5)
  • The webclient connected to any host named in the X-Process-Engine request header, also before login, and echoed the URL and connection error in the response. It now accepts only engine ids whose engine REST server is configured, as cibseven.webclient.engineRest.url / path or as an entry of cibseven.webclient.engineRest.additionalEngineRest, and rejects requests for any other server with “The requested process engine is not configured”; connection errors are answered with “The process engine could not be reached” without details. The webclient UI, embedded forms and the SSO login take the engine id from the configured servers, so they work as before (since 2.2.5)
  • The webclient’s services/v1/system/pool-status endpoint answered without authentication; it now requires a login (since 2.2.5)
  • The AI Agent Connector sent the server’s OPENAI_API_KEY to any base URL a process supplied, for example in a process variable. The key is now sent only to the endpoint configured on the server, and the connector logs a warning for other endpoints (since 2.2.5)
  • Process descriptions and warnings are rendered as text in the start process list and the warning box, closing a stored cross-site scripting (XSS) issue (since 2.2.4)
  • The Swagger UI bundled DOMPurify 3.4.13, which is affected by GHSA-cg2g-xh64-v4q7 and GHSA-mrv2-3pqr-j5jr; it now bundles DOMPurify 3.4.17 (since 2.2.5)
  • The FEEL engine of the DMN engine called external Java functions, which the DMN engine disables, when a function definition was passed as an argument, e.g. to sort(); feel-engine 1.19.6 rejects such definitions (fixes GHSA-vx3p-v6cf-vfjw)
  • The webclient no longer logs the authentication response, including the token, to the browser console (since 2.2.4)
  • Task filter JUEL expressions can be restricted to a whitelist (since 2.2.2), which is enabled by default and also accepts the expressions suggested by the Tasklist filter dialog (since 2.2.4) (fixes Camunda Security Notice 157)
  • The AI Agent Connector chat memory could be read from another process instance by reusing its memoryId (since 2.2.4)
  • Fixed a user query by id ignoring further criteria and the READ permission check (since 2.2.3)
  • Modeler: the edit lock is checked against its owner, /session/check no longer leaks the session id, and diagram XML parsing is hardened against XXE (since 2.2.1)
  • SSO: JWKS keys are matched by kid, x5t or x5t#S256, so tokens that identify their key by thumbprint are accepted

Build & Configuration

  • All artifacts are built for Java 17 and against Jakarta EE 11
  • The Spring Boot 3 and Spring Boot 4 builds are merged: the unsuffixed artifacts are built on Spring Boot 4, and the -4 artifacts are relocations
  • The engine jar shades only Gson and cron-utils; cibseven-spin-dataformat-all relocates Jackson 3, JAXB and Activation
  • GraalJS 25 is packaged as separate runtime modules in Run, Tomcat and WildFly, with icu4j packaged explicitly
  • WildFly: new Jackson 3 modules, and a module alias keeps the 2.2 module name org.cibseven.spin.cibseven-spin-dataformat-xml-dom-jakarta resolvable
  • The cibseven-bom manages json-path, json-smart and cibseven-external-task-client-jackson2, and no longer lists cibseven-engine-spring-6, the -jakarta artifacts or the legacy web applications
  • New database indexes ACT_IDX_TASK_PARENT_TASK_ID (on all databases) and ACT_IDX_HI_JOB_LOG_DEPLOYMENT speed up completing or deleting process instances with tasks and deleting deployments in cascade; building the second index on a large job log takes time, and on PostgreSQL, Oracle and SQL Server it blocks writes to ACT_HI_JOB_LOG while it is built
  • The SQL scripts of the webclient tables ship as <db>_extensions_<version>.sql and <db>_extensions_2.2_to_3.0.sql, and Liquibase applies them with the changeSet 2.2-to-3.0-extensions
  • The webclient publishes configuration metadata for IDE completion of cibseven.webclient.*
  • The modeler bundle is loaded only when the modeler is opened
  • Webjar dependencies are optional (since 2.2.3)
  • JDBC drivers are no longer on the webclient’s runtime classpath (since 2.2.2)
  • SBOMs (CycloneDX) are published for the whole project, the distributions and the Docker images
