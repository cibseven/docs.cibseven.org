CIB seven 2.1.11 EE - Release Notes

Release Date: November 19, 2026

Highlights

  • Security Attachments and comments of tasks and process instances are now protected by permission and tenant checks, enabled by default
  • Security JUEL scripts now follow the restrictions of a customized expression manager, and a new opt-in hardening adds a deny list for expressions and scripts, an allow list for task types and script languages, and an endpoint allow list for connectors
  • Security The webclient only connects to configured engine REST servers
  • Security 79 CVEs resolved (6 Critical, 11 High, 30 Medium, 32 Low), among them CVE-2026-114938 (Java4Shell, in the Java runtime of the Docker images), CVE-2026-76183 (Apache Tomcat), CVE-2026-77224 (XXE in the Java External Task Client) and CVE-2026-109431 (attachments and comments), and the others by the swagger-ui, zlib and Alpine base image updates
  • Process Instance Search (EE exclusive) Quoted values of variable criteria now match exactly, and a like criterion finds values that contain the text
  • Timers Cron time cycles no longer fire in an endless loop when clocks go back at the end of daylight saving time

Breaking Changes

  • Attachment permissions. Reading, creating, changing and deleting the attachments of tasks and process instances now requires a permission on the task or process instance, including the tenant check. Users who used attachments without such a permission now get an AuthorizationException (HTTP 403 over the REST API). Reading needs READ on the task or READ_TASK on the process definition, or READ on the process instance or READ_INSTANCE on the process definition; writing needs TASK_WORK or UPDATE on the task, or TASK_WORK or UPDATE_TASK on the process definition, or UPDATE on the process instance or UPDATE_INSTANCE on the process definition. Attachments of completed tasks and process instances are checked against the history permissions: READ_HISTORY on the process definition to read (or READ on the historic instance with enableHistoricInstancePermissions), and DELETE_HISTORY on the process definition or ALL on the historic instance to write. Attachments whose task or process instance no longer exists are available to administrators only. Setting the process engine property enforceAttachmentPermissions to false restores the previous behavior (not recommended). The checks only apply when authorization or the tenant check is enabled. See Attachment and Comment Permissions
  • Comment permissions. Creating and reading the comments of tasks and process instances, and reading task events, now requires a permission on the task or process instance, including the tenant check: READ on the task or READ_TASK on the process definition to read, TASK_WORK or UPDATE on the task or UPDATE_TASK on the process definition to add, and READ / UPDATE on the process instance or READ_INSTANCE / UPDATE_INSTANCE on the process definition for process instance comments. Comments of completed tasks and process instances follow the history permissions, so the former assignee of a completed task needs READ_HISTORY on the process definition, or READ on the historic task with enableHistoricInstancePermissions, to keep reading its comments. Creating a task comment over the REST API now answers HTTP 403 instead of 400 on a missing permission. Setting the process engine property enforceCommentPermissions to false restores the previous behavior (not recommended); updating and deleting comments stay checked either way. See Attachment and Comment Permissions
  • JUEL scripts with a customized expression manager. If the process engine uses a subclass of JuelExpressionManager, SpringExpressionManager or CdiExpressionManager, or a SpringExpressionManager with the property beans set, scripts with scriptFormat="juel" now resolve names, properties and methods through the expression manager’s resolver chain, like attribute expressions. In these cases only: the restrictions of the expression manager now apply in JUEL scripts and expressions it rejects fail; names that only the script resolver factories provided (configuration beans, Spring beans, mocks, custom ResolverFactory implementations) are no longer available; context, and with it lang:import, is no longer available; a process variable takes precedence over a bean with the same name; and unknown names fail with “Cannot resolve identifier”. Override JuelExpressionManager#isAppliedToJuelScripts to keep the previous behavior. Engines with a stock expression manager, and script languages other than JUEL, are not affected. See Custom Expression Managers
  • Swagger UI version setting. The Swagger UI now uses swagger-ui 5.34.1, which springdoc only serves when springdoc.swagger-ui.version names it. The shipped default.yml / production.yml of CIB seven Run and the configuration of the webclient set it. If you run CIB seven Run with your own configuration file, or embed the webclient in your own Spring Boot application, set springdoc.swagger-ui.version: 5.34.1; otherwise the Swagger UI answers HTTP 404

Configuration Changes

  • New process engine property enforceAttachmentPermissions (default true): permission and tenant checks for attachments, see Breaking Changes. In CIB seven Run / Spring Boot, set process engine properties via camunda.bpm.generic-properties.properties.<name>
  • New process engine property enforceCommentPermissions (default true): permission and tenant checks for comments, see Breaking Changes
  • New process engine property deniedExpressionAccess (default: not set, no deny list): a comma-separated deny list for JUEL expressions and scripts, see Security Hardening
  • New process engine property executionAllowList (default: empty, no check): a comma-separated allow list of task types and script languages, see Security Hardening
  • New process engine property expressionHardeningMode (off, report or enforce, default enforce): what happens on a violation of deniedExpressionAccess or executionAllowList once one of them is set, see Hardening Mode
  • New connector setting cibseven.connect.allowed-endpoints (system property) / CIBSEVEN_CONNECT_ALLOWED_ENDPOINTS (environment variable), and per connector cibseven.connect.<connectorId>.allowed-endpoints / CIBSEVEN_CONNECT_<CONNECTOR_ID>_ALLOWED_ENDPOINTS (default: not set, no restriction), see Security Hardening
  • The shipped configuration of the webclient and CIB seven Run sets springdoc.swagger-ui.version: 5.34.1, see Breaking Changes

New Features

Security Hardening

All three lists are off by default, so an engine behaves as before until an administrator sets them.

  • Deny list for expressions and scripts: deniedExpressionAccess names what JUEL expressions and scripts must not access: a property or method name (getClass), a type (java.lang.Runtime), an EL function (lang:import) or a member of a type (com.example.Admin#delete). It applies to BPMN and CMMN expressions, JUEL scripts, DMN JUEL expressions and the legacy FEEL engine, not to other script languages. Any entry switches the list on, together with the defaults class, getClass, java.lang.Class, java.lang.ClassLoader, java.lang.reflect.AccessibleObject, java.lang.invoke.MethodHandle, java.lang.invoke.MethodHandles, lang:import, org.cibseven.bpm.engine.impl.cfg.ProcessEngineConfigurationImpl, java.lang.Runtime and java.lang.ProcessBuilder; a leading minus removes a default (e.g. -lang:import). A newly denied EL function can stop deployed process definitions from loading, so run with expressionHardeningMode=report first, which only logs violations
  • Allow list for task types and script languages: once executionAllowList has entries, process definitions can only use the listed built-in task types (shell, mail, external) and script languages, checked at deployment and at execution. For example, external, mail, juel, groovy, javascript, feel allows mail tasks and denies shell tasks
  • Endpoint allow list for connectors: cibseven.connect.allowed-endpoints restricts the endpoints the HTTP and SOAP connectors (including redirects) may contact, so that targets taken from process variables cannot send requests and credentials elsewhere. Entries have the form scheme://[*.]host[:port], separated by commas. A connector’s own setting (cibseven.connect.<connectorId>.allowed-endpoints, e.g. http-connector or soap-http-connector) replaces the global one, and * exempts it

Bug Fixes

Security

  • Attachments of tasks and process instances could be read, downloaded, changed and deleted by any authenticated user who knew their id, since the engine did not check any permission; comments could be read and added the same way. Both are now checked, see Breaking Changes (fixes CVE-2026-109431)
  • JUEL scripts (scriptFormat="juel") ignored the restrictions of a customized expression manager that applied to attribute expressions, so a restricted call such as reflection could still run in a script task. They now resolve through the expression manager, see Breaking Changes
  • The Java External Task Client resolved external entities when it deserialized application/xml object variables, so a crafted variable could make a worker read local files and send requests to other hosts. External entities and DOCTYPE declarations are now rejected, also with a DocumentBuilderFactory supplied by the application (fixes CVE-2026-77224)
  • The Docker images now ship a Java runtime with the fix for CVE-2026-114938 (“Java4Shell”). The ZIP distributions and the Spring Boot starter run on your own JDK: update it to 17.0.21.1 or 21.0.13.1 or later, or start the JVM with -XX:-UseBASE64Intrinsics until you can
  • The webclient connected to any host named in the X-Process-Engine request header, also before login, and echoed the URL and connection error in the response. It now accepts only engine ids whose engine REST server is configured, as cibseven.webclient.engineRest.url / path or as an entry of cibseven.webclient.engineRest.additionalEngineRest, and rejects requests for any other server with “The selected process engine is not configured”; connection errors are answered with “The process engine could not be reached” without details. The webclient UI, embedded forms and the SSO login take the engine id from the configured servers, so they work as before
  • The webclient’s services/v1/system/pool-status endpoint answered without authentication; it now requires a login
  • Process names and error messages are now rendered as text in the start process dialog and error dialogs, closing a stored cross-site scripting (XSS) issue. Typing ( into the process search no longer causes an error
  • The Swagger UI bundled DOMPurify 3.4.13, which is affected by GHSA-cg2g-xh64-v4q7 and GHSA-mrv2-3pqr-j5jr; it now bundles DOMPurify 3.4.17

Timers

  • Fixed cron time cycles such as 0 0/15 * * * ? firing in an endless loop when clocks go back at the end of daylight saving time
  • Fixed a backward-compatibility regression in the legacy Quartz cron syntax support (out-of-range steps, whitespace, day and month names in steps)

Attachments

  • Creating an attachment for a completed process instance no longer fails with HTTP 500, and attachments of completed tasks and process instances now get the removal time, so the history cleanup removes them
  • Unknown task, process instance or attachment ids now fail with a clear error instead of an IndexOutOfBoundsException or NullPointerException

Process Instance Search (EE exclusive)

  • Fixed variable criteria with a quoted value in the process instance search: with =, !=, >, >=, < or <=, a quoted value such as "0100" is now sent as a string without the quotes, so it finds the variable; before, the quotes were sent along and nothing matched. Unquoted values are unchanged
  • A like value is now always sent as a string and wrapped in % unless it already starts or ends with %, so like 100 finds the String variables 100, 0100 and 1005. Switching a criterion from like to another operator removes the surrounding %. Saved searches, last-used criteria and URLs with like 100 therefore now also find 0100 and 1005. The engine compares like only for String variables, so an Integer variable 100 is found with = 100, not with like

Technical Updates

Dependency Updates

  • Update Apache Tomcat from 10.1.59 to 10.1.61 and from 9.0.121 to 9.0.123 (Tomcat distribution and CIB seven Run), fixing CVE-2026-76183
  • Update swagger-ui from 5.32.14 to 5.34.1 (DOMPurify 3.4.17)
  • Update @cib/common-frontend from 1.0.2 to 1.0.2-hotfix1
  • Update zlib from 1.3.2-r1 to 1.4-r0 (Alpine base image), fixing CVE-2026-4738
  • Update openssl (libcrypto3, libssl3) from 3.5.8-r0 to the latest Alpine 3.5 package (3.5.9-r0 or later) (Alpine base image) (since 2.1.10 hotfix)
  • Update the Java runtime to 17.0.21.0.3 (openjdk17-jre-headless, Java 17 images) and from 21.0.12 to 21.0.13.0.3 (openjdk21-jre-headless, Java 21 images) (Alpine base image), which blocks the compromised eMudhra intermediate CA certificates (since 2.1.10 hotfix)
  • Update the Java runtime from 17.0.21.0.3 to 17.0.21.1 (openjdk17-jre-headless, Java 17 images) and from 21.0.13.0.3 to 21.0.13.1 (openjdk21-jre-headless, Java 21 images) (Alpine base image), fixing CVE-2026-114938 (Java4Shell)
  • Update ca-certificates to 20261020 (Alpine base image), which no longer trusts emSign ECC Root CA - G3 (since 2.1.10 hotfix)
  • Update brotli from 1.2.0-r0 to 1.2.1-r0, curl / libcurl from 8.22.0-r0 to 8.23.0-r0, libxslt from 1.1.43-r3 to 1.1.43-r4 and musl from 1.2.5-r23 to 1.2.5-r24 (Alpine base image)

Resolved CVE Vulnerabilities

Critical Severity
  • CVE-2026-111497 - Buffer overflow in the Brotli decoder (versions 1.0.3 through 1.2.0) lets a remote attacker corrupt decoder memory, disclose memory contents, cause a denial of service or possibly execute code. Affects brotli-libs. - CVSS 8.1.
  • CVE-2026-114820 - Critical vulnerability in a package of the Docker images, resolved by the package updates above. (since 2.1.10 hotfix)
  • CVE-2026-46470 - Critical vulnerability in a package of the Docker images, resolved by the package updates above. (since 2.1.10 hotfix)
  • CVE-2026-76183 - Authentication bypass by alternate name in Apache Tomcat lets an attacker bypass the security constraints of WebSocket endpoints (Camunda Security Notice 171). CIB seven itself has no WebSocket endpoints; applications deployed into the Tomcat distribution that use them are affected. Fixed by Tomcat 10.1.61 and 9.0.123. Affects org.apache.tomcat. - CVSS 9.8.
  • CVE-2026-91403 - eMudhra generated weak private keys for 8 intermediate CAs, so TLS certificates that chain to them can be forged. This exposes outbound TLS connections from the container that use the default Java truststore, e.g. the HTTP connector, OIDC/JWKS or mail. Affects the Java truststore (openjdk, ca-certificates). - CVSS 9.1. (since 2.1.10 hotfix)
  • GHSA-cg2g-xh64-v4q7 - Sanitizer bypass in DOMPurify 3.4.4 to 3.4.16, bundled with the Swagger UI of the webclient and CIB seven Run. The Swagger UI does not use the affected DOMPurify options. Affects org.webjars:swagger-ui (dompurify).
High Severity
  • CVE-2026-107891 - Vulnerability in the musl C library, resolved by the updated Alpine package. Affects musl, musl-utils.
  • CVE-2026-109431 - Missing authorization checks let authenticated users without any permission read, download or delete the attachments and read the comments of tasks and process instances, knowing only their id. Affects the process engine and the engine REST API. - CVSS 7.3.
